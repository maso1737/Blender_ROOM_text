光を下から
駆け上げる。

円周に並べた J 字のレールを、色とりどりの光が下から上へ走り抜けます。キーフレームは1つも打ちません。フレーム番号から「いまどこを走っているか」を直接計算するので、尺を変えても速度を変えても壊れません。

はじめての人へ：手順は10ステップですが、詰まるところは3か所だけです。03（ドメイン）・04（順番）・10（光らせ方）。ここだけ落ち着いて読めば、あとは繋ぐだけです。

01CURVE

J 字のレールを手で描く

ノードではなく、ふつうのカーブオブジェクトを1本置きます。ベジエ3点。床を走って、裾で立ち上がって、まっすぐ上へ抜ける形です。

垂直部はローカル X = 0 に置いてください。02 で作る円（半径 Radius）の上に、ちょうど乗るようにするためです。
ずれるとどうなる？
レールの立ち上がりが円からはみ出して、円筒の壁がガタガタになります。X=0 に置いておけば、円をどれだけ大きくしても壁はまっすぐのままです。
Cyclic は OFF。閉じたカーブには Trim Curve が効きません。05 で光が動かなくなります。
A はカメラの画角の外まで伸ばします。ループが一周して光が「湧く」瞬間はどうしても不自然なので、見えない場所で起こしてしまうのがコツです。
形は好きに変えてOK。B の X で裾の張り出し、C のハンドルの長さで裾のなだらかさが決まります。

Resample の Count は 600。ここをケチると 07 の点線が解像せず、干渉縞（モアレ）になります。
600 の根拠
カーブ全長が約17mなので、600点なら点の間隔が約2.8cm。07 で作る点線の周期（既定20cm）に対して7点あるので、きれいに解像します。200点だと間隔8.5cmで、点線のほうが細かくなって破綻します。
本数を Curve Circle の Resolution で決めないでください。60本つくっておいて、Index > Count の Delete Geometry で減らします。
なぜ遠回りするのか
あとで「冒頭に一気に本数が増える」ワイプをやるときに、Count というただの数値にキーを打つだけで済むからです。Resolution を直接アニメーションさせると、増えるたびに全部のレールの位置が変わってしまいます（拡張編）。
Axis = X の意味。01 で「床の走りをローカル +X」に描いたので、その +X が円の外側を向きます。Pivot = Z は「Z 軸まわりにだけ回す」＝レールが倒れない、という意味です。
03KEY

1本に1つの値を配る

「このレールは何色か」「どれくらい速いか」「どこからスタートするか」を、レール1本につき1つずつ決めます。この手順書で一番大事な設計判断です。

Domain を Instance にしてください。初期値の Point のままだと、1本のレールの中で色が虹色にバラけます。
なぜ Point だとバラけるのか
次の 04 で Realize Instances を通すと、それまで「60本のインスタンス」だったものが「36万個の点」になります。Point ドメインで Random Value を引くと、その点ひとつひとつが別の乱数をもらってしまう。
Instance ドメインなら、まだ「60本」だった時点で値が決まるので、1本につき1つの値が保証されます。
捕まえた値はこのあと Realize と Trim を通り抜けて、最後まで届きます。
seed は好きな数字でOK。3つとも違う数字にしてください。同じだと、速い球がいつも同じ色になります。
04GEO

レール上の位置を先に覚えておく

実体化してから、「レールの根元から何メートルの地点か」を全部の点に覚えさせます。07 の点線をレールに貼り付けるための仕込みです。やる順番が全てです。

この Capture は Trim の「前」に置きます。Trim のあとだと、点線が光と一緒に滑っていってしまいます。
なぜ滑るのか
Trim のあとの Spline Parameter は、切り取った光の区間で 0→1 に振り直されます。つまり「光の中での位置」になってしまう。それを使って点線を作ると、点線が光にくっついて動きます。
Trim の前に「レールの根元から何メートルか」を覚えておけば、Trim はその値を引き継ぐだけなので、点線はレールに貼り付いたまま動きません。LEDテープの上を光が通っていく、という絵にはこちらが必要です。
Realize Instances は Trim より前。Realize しないと、60本が同じカーブデータを参照したままなので、全部のレールが一斉に光ります。

07GEO

点線にする

ベタ塗りの光ではなく、LEDテープのような粒々にします。04 で覚えておいた arc をここで使います。

DotDensity の単位は「1メートルあたりの本数」です。周期 = 1 ÷ DotDensity。5 なら 20cm おき。
大きい数字を入れると壊れます
04 で捕まえた arc は Spline Parameter の Length、つまりメートルの値です。0〜1 の割合ではありません。
ここに 140 のような数字を入れると周期が 7mm になり、02 の Resample の点間隔（2.8cm）より細かくなって、点線ではなく干渉縞（モアレ）が出ます。実用上の上限は 12 くらいです。
しきい値 0.5 は「点と隙間が半々」という意味です。0.7 にすると点が短く、0.3 にすると点が長くなります。

Color Ramp の Interpolation は Constant。Linear のままだと色が混ざって「1本1色」になりません。
Maximum(dot, head⁴) がこのステップの肝です。頭のところだけ点線の隙間が埋まってベタ光りになり、尾に向かって点線に戻ります。
これが無いとどうなるか
光が点線に食われて、画面全体が「ただの破線の壁」に見えます。頭が solid になることで初めて「玉が走っている」と読めるようになります。head⁴ は「頭のごく近くだけ 1 に近づく」カーブです。
Attribute の Type は Geometry のままでOK。04 で Realize 済みなので、属性はメッシュの点そのものが持っています（インスタンスのままなら Instancer が要りますが、この組み方では不要です）。

EEVEE の Bloom は無くなりました。昔のチュートリアルに出てくる Render Properties の「Bloom」チェックは、5.2 には存在しません。光の滲みは Compositing タブの Glare ノードで作ります。3Dビューで見たいときは、ビューポート右上の Viewport Compositing を ON。
View Transform が Filmic のままだと、絶対にあの見た目になりません。Standard に変えてください。見た目の差で一番効く設定です。
Filmic だと何が起きるか
黒が浮いてグレーになり、色が眠くなります。参照にあるような「真っ黒の中に鮮やかな発光」は、Filmic の性質上どうやっても出ません。明るさをいくら上げても解決しないので、先にここを疑ってください。
電球の位置にライトを置かないこと。数百個のライトは EEVEE でも破綻します。Emission マテリアル＋Glare だけで絵は成立します。

Extra / 拡張編

ワイプをつける

「冒頭で一気に増えて、最後は中央に寄って一本の柱になり、そのまま上へ抜ける」——これを後から足せるように、02 で下ごしらえしてあります。ノードは1つも足しません。

X1ANIM

数値2つにキーを打つだけ

モディファイアのパネルに出ている Count と Radius に、普通のプロパティと同じように I キーでキーフレームが打てます。

冒頭「一気に増える」
Count を 0 → 60
最後「中央に寄って柱になる」
Radius を 3.3 → 0
そのまま上へ抜ける
Speed を上げる／カメラを上へ
02 で「本数を Resolution で決めない」「半径を1つの値にまとめる」を守っておいたのは、このためです。どちらも数値1つなので、グラフエディタでイージングまで作り込めます。
散らすときは Motion Blur を ON に。尾が引いた瞬間に「本当に動いた」ように見えます。
X2GEO

J 字を手描きせずに作る

形を数値で管理したくなったとき用。01 の手描きカーブを、ノードだけで置き換えられます。

Mesh Line（3点）→ Mesh to Curve→ Fillet Curve→ 02 の Object Info の代わりに
Fillet Curve の Radius が「裾のなだらかさ」になります。手描きの C のハンドルに相当します。
ただし最初は手描きのほうが速いです。形が決まってから置き換えるくらいでちょうどいいです。

属性は4つだけ

ジオメトリノードで作る属性と、その行き先の対応表です。この4行が頭に入れば全体が掴めます。

思ったとおりに出ないとき

この6つで、ほぼ全部が直ります。上から順に確認してください。

1 ／ 光らない・真っ黒

View Transform が Filmic ではありませんか。Standard にしてください（10）。次に Compositing の Glare が繋がっているか。EEVEE の Bloom チェックはもう存在しません。

2 ／ 1本のレールの中で色が虹色にバラける

Capture Attribute の Domain が Point のままです。Instance に変えてください（03）。

3 ／ 全部のレールが一斉に光る

Realize Instances が Trim Curve より後ろにあります。Realize 前はインスタンスが同じカーブデータを参照しているので、差が付きません（04）。

4 ／ 点線が光と一緒に滑っていく

arc の Capture Attribute が Trim より後ろにあります。前に移してください（04）。

5 ／ 点線ではなく干渉縞（モアレ）が出る

DotDensity が大きすぎます。単位は1メートルあたりの本数で、実用上限は 12 くらい。あわせて Resample Curve の Count が 600 あるか確認してください（07）。

6 ／ 筒が極太の円盤になる／太さが変わらない

太さは Curve to Mesh の Scale 入力で変えます。5.x は Set Curve Radius の半径属性を暗黙には見てくれません（06）。
あわせて、Trim Curve はカーブが Cyclic だと効きません（01）。
